# Замовлення та доставки у Telegram

## Як працює потік замовлення

1. Клієнт збирає кошик на сайті або відкриває той самий сайт кнопкою меню в Telegram.
2. Під час оформлення сайт надсилає на `/api/orders` лише ID страв і кількість. Сервер повторно звіряє позиції та ціни з меню в репозиторії.
3. API записує замовлення, склад, суму страв і подію створення в PostgreSQL. Потім бот надсилає картку замовлення до групи адміністраторів.
4. Адміністратор приймає замовлення кнопками, змінює статус і вказує вартість доставки.
5. Після оформлення сайт пропонує відкрити підписане посилання на бота. Після натискання Start бот прив’язує замовлення до Telegram-акаунта та показує склад, суму й поточний статус. Подальші зміни статусу приходять у цей чат; статус також можна оновити кнопкою в картці замовлення.
6. Якщо клієнт оформив замовлення у Telegram Mini App, бот уже має перевірений Telegram ID і може надсилати оновлення без повторного прив’язування.

Замовлення зберігається до надсилання сповіщення. Якщо Telegram тимчасово недоступний, API повертає успішний номер замовлення з ознакою `notificationPending`; адміністратор може виконати `/orders`, щоб повторно надіслати активні замовлення.

## Статуси та дії адміністратора

`Нове → Прийняте → Готується → Готове → У дорозі → Доставлене`

Замовлення можна скасувати до завершення. Для самовивозу на етапі «Готове» є дія «Видати замовлення». Для доставки адміністратор задає вартість у гривнях відповіддю на запит бота. На етапі «Готове» адміністратор сам переводить доставку у статус «У дорозі»; призначення кур’єра в боті немає. Вартість доставки не розраховується автоматично. Оплата — при отриманні.

## Підключення бази даних

Потрібен PostgreSQL. Рекомендовано створити базу в Neon і зберегти connection string як `DATABASE_URL`. Драйвер `@neondatabase/serverless` виконує параметризовані запити через HTTP, що підходить для serverless-функцій Vercel.

Виконайте SQL з [`db/migrations/001_orders.sql`](../db/migrations/001_orders.sql) у SQL Editor бази. Міграція створює таблиці замовлень, позицій, історії дій та запитів на вартість доставки.

Для прив’язування замовлення до Telegram використовується наявне поле `orders.telegram_user_id`; окремої міграції для відстеження не потрібно.

## Telegram і змінні середовища

1. Створіть бота через `@BotFather` і збережіть його токен у `TELEGRAM_BOT_TOKEN`.
2. Запустіть бота приватно командою `/start`; він покаже ваш Telegram ID. Додайте його до `TELEGRAM_ADMIN_IDS`.
3. Додайте бота в приватну групу працівників. Після налаштування вебхука виконайте в групі `/chatid@ім’я_бота`; бот відповість ID групи. Збережіть його як `TELEGRAM_ADMIN_CHAT_ID`.
4. Задайте `SITE_URL` як HTTPS origin сайту, а `TELEGRAM_WEBHOOK_SECRET` як випадковий секрет з латинських літер, цифр, `_` та `-`.
5. Задайте публічний username бота без `@` у `TELEGRAM_BOT_USERNAME`; після оформлення сайт запропонує перейти у бот для відстеження замовлення.

Додайте ці змінні у Vercel → **Project Settings → Environment Variables** для Production і Preview. Спочатку залиште `ORDERS_ENABLED=false`, розгорніть сайт, застосуйте міграцію та перевірте Telegram webhook. Після налаштування змінних `DATABASE_URL`, токена, секрету webhook, ID адміністратора й чату та `SITE_URL` встановіть `ORDERS_ENABLED=true` у Vercel і виконайте redeploy. Для локального запуску скопіюйте `.env.example` у `.env` і заповніть значення. Секрети не додавайте до Git і не надсилайте в чат.

Після деплою запустіть `npm run telegram:webhook`, щоб зареєструвати Telegram webhook. Скрипт бере налаштування з локального `.env` та вказує Telegram надсилати `message` і `callback_query` на `/api/telegram/webhook`. Endpoint перевіряє заголовок `X-Telegram-Bot-Api-Secret-Token`.

## Локальна розробка

```sh
npm install
copy .env.example .env
npm run dev
```

`npm run dev` збирає сайт і запускає статичні файли разом із `/api/orders` та `/api/telegram/webhook` на `http://127.0.0.1:4173`. Для тестування Telegram webhook потрібен публічний HTTPS deployment.

## Технічні межі першої версії

- Зберігається телефон клієнта, адреса доставки, коментар до замовлення, склад замовлення та історія зміни статусів.
- Онлайн-оплати немає. Оплата при отриманні.
- Тарифних зон доставки й автоматичного розрахунку вартості немає.
- Telegram ID із Mini App приймається лише після серверної перевірки `Telegram.WebApp.initData`. Для замовлень із браузера використовуються підписані deep links із HMAC на серверному токені бота; прив’язане замовлення не можна перезаписати іншим Telegram-акаунтом.
- Адміністративні callback-кнопки працюють тільки для ID з `TELEGRAM_ADMIN_IDS` і в `TELEGRAM_ADMIN_CHAT_ID`.
- Команди `/start` і `/menu` доступні в приватному чаті. У робочій групі адмін бачить `/orders` і `/chatid` у меню команд.
- Зареєструйте меню Telegram командою `npm run telegram:commands` після налаштування локального `.env`.
